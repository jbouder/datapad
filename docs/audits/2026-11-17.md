# Web App Audit — datapad

**Audited:** 2026-11-17 · **Commit:** `6657f5d` on `v2` · **Scope:** full (25 dimensions), plus an accessibility pass, before cutover (#342)
**Stack:** React 19 + Vite + Tailwind v4 (Beskar, shadcn base-lyra), Cloudflare Workers, one SQLite-backed Durable Object per verified email, R2 backups, KV for MCP OAuth, Cloudflare Access in front, bun, Biome, Vitest in workerd, Playwright + axe
**Compared with:** [2026-10-28](2026-10-28.md) (`2a28992` on `main`, 2.9 / 4)

## Summary

**Overall maturity: 3.4 / 4** (up from 2.9). v2 rebuilt most of the app
and the security boundary held. The M18 follow-ups closed almost every
finding from the last audit.

What changed since October 28:
- **Security went from 3.1 to 3.9.** Sockets close when the Access
  session ends. PKCE is always required. HSTS is on. The deploy refuses
  an empty `ACCESS_AUD` or a set `DEV_ACCESS_EMAIL` in every environment.
  `apply()` holds MCP to an op allowlist. Each has a test.
- **Operations went from 2.6 to 3.4.** A newer stored schema is refused,
  and there is a rollback runbook. Request ids, client error reports, a
  visible version, Bun pinned, coverage floors, license and knip checks
  are all in CI.
- **Frontend performance went from 1 to 2.** Pages are split, and hashed
  assets are cached for a year. The first load is still about 389 KB
  gzip, and no budget guards it.

What is new in v2 and was audited for the first time: Today (day and
week), the capture line, Scratch, the project and person rooms, meeting
mode, All with its layouts, saved views and Rooms chip, Settings for v2,
the schema 3 to 5 migration (export format 3), the v2 MCP tools and the
staging Worker.

No cutover blocker was found. One latent data bug was found and fixed in
this PR (see Status): the format 3 migration ran again on every later
schema bump.

### Top risks

1. **Every later schema bump re-ran the format 3 migration over live data** (Data integrity). It would bring back checklist notes the owner deleted and mark decided tasks to decide again. Fixed in this PR. `worker/datapad.ts:575`
2. **Merging to `main` migrates production one way, with no approval gate** (Release). Schema 5 makes older code refuse the object. The `production` environment has no required reviewer. Take the export and backup check in #342 first.
3. **The reporting channel in `SECURITY.md` does not work** (Repo health). It points at private vulnerability reporting, which is off. `SECURITY.md:8-10`
4. **No size budget, and the first load is about 389 KB gzip** (Frontend performance). Today, Scratch and the rooms are in the first load on purpose, and the shared `shortcuts` chunk is 396 KB raw. `.github/workflows/ci.yml:52`
5. **Open v1 tabs can still send list and Notepad ops after cutover** (Data integrity). The reducer accepts them and v2 does not show the result. Nothing is lost. `shared/reducer.ts:747-769,948-984`

## Findings

Ranked most severe first across all dimensions. **Fixed here** means fixed
in the PR that adds this report.

### 🔴 High

- **Every later schema bump re-ran the format 3 migration over live data** — Data integrity. **Fixed here.**
  - Evidence: `worker/datapad.ts:575` ran `migrateSpaceDocs(FORMAT3_READ, migrateFormat3)` whenever `version < SCHEMA_VERSION`, with no `version < 4` guard. List rows are kept forever, and `migrateFormat3` makes a note for any list whose note is missing (`shared/migrate.ts:205-213`). `toDecide()` marks any open task tagged `decide` (`shared/migrate.ts:236-243`).
  - Impact: the 3 to 5 cutover was safe. At schema 6, checklist notes the owner had deleted would come back, and tasks the owner had marked decided would be marked to decide again. A staging object that went from 4 to 5 may already show this.
  - Fix: format 3 runs only below schema 4; schema 4 runs `migrateSettings` alone. A workerd test starts at schema 4 with a deleted list note and a decided tagged task and checks both stay as they were.

### 🟡 Medium

- **Merging to `main` migrates production one way, with no approval gate** — Release
  - Evidence: the `production` environment has no protection rules. A green CI run on `main` deploys on its own. After schema 5, older code answers `NEWER_SCHEMA` (`worker/datapad.ts:558`).
  - Impact: if the export and backup check are skipped, the only way back is a fresh object and an older backup.
  - Fix (owner): take the export and confirm an R2 backup before merging (#342 says so). Consider a required reviewer on `production`.
- **The `SECURITY.md` reporting channel does not work** — Repo health
  - Evidence: `SECURITY.md:8-10` points at `/security/advisories/new`; `gh api repos/jbouder/datapad/private-vulnerability-reporting` returns `{"enabled":false}`.
  - Fix (owner): turn on private vulnerability reporting. This was half of #230.
- **No size budget; the first load is about 389 KB gzip** — Frontend performance
  - Evidence: the entry chunk is 142 KB gzip and preloads `shortcuts-*.js` (113 KB), `usePageTitle-*.js` (84 KB) and `dropdown-menu-*.js` (47 KB). Today, Scratch and the rooms are in the first load on purpose (`src/components/AppShell.tsx:38-42`). `ci.yml:52` builds with no size check.
  - Fix: a budget step after the build (first-load JS about 400 KB gzip, CSS about 30 KB, WebLLM never in it). Then find what makes the `shortcuts` chunk 396 KB raw.
- **Open v1 tabs can still send retired ops after cutover** — Data integrity
  - Evidence: list ops and `writeNotepad` are still in `OpSchema` and the reducer (`shared/protocol.ts:1271-1307`, `shared/reducer.ts:747-769,948-984`). The client has no version handshake.
  - Impact: a list added from a stale tab logs an Activity line but never shows in v2. A Notepad note written from one carries `scratch: true`, and `moveNote` refuses to file it (`shared/reducer.ts:725`). Nothing is lost; it is kept and exported.
  - Fix: make the retired ops refuse with "Reload Datapad", or add a build version to `/ws` and reload on a mismatch. Decide the same for the Decision ops.
- **Undo of a task deleted from its panel skipped the reducer's checks** — Data integrity. **Fixed here.**
  - Evidence: `src/components/tasks/TaskPanel.tsx:191` called `actions.put()`. The checked `restoreTask` op existed but had no UI caller.
  - Fix: Undo sends `restoreTask`. The template forms still Undo through `put` (`src/components/templates/TemplateForm.tsx:132`, `NoteTemplateForm.tsx:88`): follow-up.
- **Staging only deploys on dispatch** — CI/CD (drift)
  - Evidence: `workflow_run` reads the default branch's workflow, and `main`'s `deploy.yml:9` lists only `main`. Every `v2` deploy so far was a `workflow_dispatch`.
  - Impact: staging can fall behind `v2` silently. It fixes itself at cutover.
- **`npm run deploy` on a `v2` checkout deploys to production** — Deployment
  - Evidence: `package.json:11` sets no `CLOUDFLARE_ENV`; README and `docs/self-hosting.md:70` give that command.
  - Impact: before cutover, one local command would migrate production early. Moot after cutover, while staging stays.
  - Fix: a `deploy:staging` script and a staging `tail`, if staging is kept (#342 decides).

### 🟢 Low

- **Loop titles and a person's topics were 36px tall on phones** — Accessibility. **Fixed here.** The title button in `src/components/today/LoopRow.tsx:53` and the topic link in `src/pages/PersonRoom.tsx:201` were `min-h-9`. They are 44px on touch now, with the row's padding moved so the row height is unchanged. `e2e/reflow.spec.ts` and `e2e/person-room.spec.ts` measure them.

- **Plain "Loading…" in the rooms and Settings** — UX. `src/pages/ProjectRoom.tsx:157`, `PersonRoom.tsx:116`, `RoomsPage.tsx:33` and four Settings sections.
- **`Unfiled` aliases for a name that never shipped** — AI/agent. `list_unfiled` and `get_today`'s `unfiled` field (`worker/mcp/tools/loops.ts:82-83,202-214`). Owner's call before v2.0.0.

- **The share image still says "events"** — UX. `scripts/icons.ts:44`, rendered into `public/og.png`.
- **No size ceiling for a space held in memory** — Scalability. `docs/architecture.md:158`.

## Accessibility pass

- **axe coverage.** Every v2 page has an `expectAccessible` check, desktop and phone: Today day (`e2e/today.spec.ts`, `e2e/a11y.spec.ts`) and week (`e2e/today-week.spec.ts`), Scratch, the project room and its tabs, the person room, meeting mode (`e2e/meeting-mode.spec.ts`, `/meetings/e-1` in `a11y.spec.ts`), All with every kind, layout and the Rooms chip (`e2e/all.spec.ts`, `e2e/all-views.spec.ts`), and every Settings section. This PR adds the week, `?show=rooms`, the room overview and All's five layouts to the both-themes list; all 96 data checks pass locally.
- **Drags.** Three drags remain: All's task board (each card's Move to… menu), a meeting's topics (Alt+↑/↓ and the topic's menu) and the whiteboard. Each has a keyboard and a touch way, as `docs/accessibility.md` lists. The timeline's point drag is wired only in the dev components page.
- **Focus order on Today.** DOM order is the visual order: the day and its controls, the capture line, Brief me, Next up, Due, the recap, the timeline, then the open loops beside it (below it on phones). No CSS `order`, reversed flex or positive `tabIndex` anywhere in `src/`.
- **44px targets.** Two were short on touch (loop titles and person-room topics, fixed above). Meta links under a row are 24px and spaced apart, which WCAG 2.5.8 allows. Capture chips are not controls except the kind chip, which is 44px.
- **Hover-only controls.** None. No `group-hover` reveal, `hover:` display or `onMouseEnter` in `src/` outside `components/ui`. The topic drag handle hides on `hover-none` devices, where the menu does the same job.
- **Not done.** The manual VoiceOver checks in `docs/accessibility.md` are still not recorded.
